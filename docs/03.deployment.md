# 部署与运维

SiteHangar 支持两种部署方式：

| 方式       | 适用场景   | 组成                                            |
| -------- | ------ | --------------------------------------------- |
| **线下测试** | 本地开发调试 | Docker 单容器（Nginx + Vite dev server + Express） |
| **线上部署** | 生产服务器  | Nginx + Node.js（后端）+ 静态文件（前端 dist）            |

***

## 一、线下测试（Docker + Vite HMR）

本地开发使用单一 Docker 容器，内含 Nginx + Vite dev server（HMR）+ Express（tsx watch），挂载本地代码和数据目录，改代码即时生效。

### 1. 目录约定

| 环境          | 站点数据目录                | 编译输出目录                 | 项目代码目录 |
| ----------- | --------------------- | ---------------------- | ------ |
| 示例（example） | `example/`            | `example/build/`       | 项目根目录  |
| 本地数据        | `my_sites_data/data/` | `my_sites_data/build/` | 项目根目录  |

容器内统一使用 `/app/site_data` 作为站点数据目录，`/app/hanger` 作为项目代码目录。`example/conf/config.yaml` 提供站点级配置（如 `buildOutputDir`、ICP 备案号），`example/build/` 是网站服务实际读取的编译结果。

如果使用软链接引用外部站点数据（例如 `example/data` 指向 `my_sites_data/data`），需要额外挂载外部数据目录到 `/app/my_sites_data`：

```powershell
docker run -d --name site-hangar -p 80:80 -p 5173:5173 -p 3000:3000 `
  -v <项目根目录>\example:/app/site_data `
  -v <项目根目录>:/app/hanger `
  -v <数据目录>:/app/my_sites_data `
  site-hangar
```

### 2. 构建镜像

Dockerfile 位于 `docker/Dockerfile`：

```powershell
docker build -t site-hangar -f docker/Dockerfile .
```

### 3. 启动容器

```powershell
# 1. 先编译示例数据
python tools/builder/build_service.py --clean --data-root example/data --output-dir example/build

# 2. 启动容器（挂载 example 作为站点数据，项目根目录作为代码）
docker run -d --name site-hangar -p 80:80 -p 5173:5173 -p 3000:3000 `
  -v <项目根目录>\example:/app/site_data `
  -v <项目根目录>:/app/hanger `
  site-hangar
```

### 4. 挂载路径说明

| 宿主机路径      | 容器内路径            | 说明                                |
| ---------- | ---------------- | --------------------------------- |
| `example/` | `/app/site_data` | 站点数据（包含 `conf/`、`data/`、`build/`） |
| 项目根目录      | `/app/hanger`    | 项目代码（`src/client`、`src/server` 等） |

`example/data/` 可以通过软链接引用外部站点数据目录，无需额外挂载到容器。

### 5. 访问地址（示例）

实际可访问的域名由 `example/data/` 下的站点目录名决定。以本仓库示例数据为例，配置对应 hosts 后可通过以下域名访问：

| 地址                             | 说明          |
| ------------------------------ | ----------- |
| `http://travel.test.local`     | 示例项目 - 中国旅游 |
| `http://science.example.local` | 示例项目 - 理科知识 |
| `http://data.format.show`      | 数据格式展示站点    |

本地测试时，需在宿主机 `hosts` 文件中添加指向 `127.0.0.1`：

```
127.0.0.1  travel.test.local science.example.local data.format.show
```

> 注意：`localhost` 不会匹配任何站点目录，访问将返回 404。后端严格根据请求 Host 头匹配数据目录，未匹配到站点时返回 `SITE_NOT_FOUND`。

### 6. 容器进程管理

容器内由 Supervisor 管理三个进程：

| 进程      | 端口   | 说明                     |
| ------- | ---- | ---------------------- |
| backend | 3000 | Express 后端，提供 API      |
| vite    | 5173 | Vite dev server，支持 HMR |
| nginx   | 80   | Nginx 反代，统一入口          |

### 7. 启动流程

容器启动时执行以下步骤：

1. **引导入口**：执行 `/app/entrypoint.sh`。
2. **处理软链接**：如果 `example/data` 或 `example/conf` 是指向 `/app/my_sites_data` 的软链接，则重建链接。
3. **读取** **`buildOutputDir`**：从 `config.yaml` 解析，未配置则默认使用 `/app/site_data/build`。
4. **复制 node\_modules**：将镜像内预装的依赖复制到 `/app/hanger/src/client/node_modules` 和 `/app/hanger/src/server/node_modules`（仅当挂载目录为空时）。
5. **复制 nginx.conf**：从 `config.yaml` 所在目录复制到 Nginx 配置目录。
6. **启动 Supervisor**：管理 backend、vite、nginx 三个进程。

`entrypoint.sh` 启动时**不自动编译**数据。修改源数据后需手动运行 `build_service.py` 重新编译。

### 8. 数据编译命令

```powershell
# 全量编译示例数据
python tools/builder/build_service.py --clean --data-root example/data --output-dir example/build

# 增量编译
python tools/builder/build_service.py --data-root example/data --output-dir example/build

# 预览模式（不写入文件）
python tools/builder/build_service.py --dry-run --data-root example/data --output-dir example/build
```

### 9. 热重载与目录更新

- **前端**：挂载本地代码目录，Supervisor 启动 `npm run dev`（Vite dev server），HMR 通过 Nginx WebSocket 代理正常工作。
- **后端**：挂载本地代码目录，Supervisor 启动 `npm run dev`（实际使用 `tsx watch`），文件变更自动重启后端。
- **Nginx 配置**：`nginx.conf` 在容器启动时从 `config.yaml` 所在目录复制，修改后重启容器生效。
- **node\_modules**：首次启动时从镜像复制到 `/app/hanger/src/client/node_modules` 和 `/app/hanger/src/server/node_modules`。
- **数据目录变更**：新增栏目、分类或页面后，需**重新编译**并刷新页面生效。

### 10. 停止与日志

```powershell
# 停止容器
docker stop site-hangar

# 查看日志
docker logs site-hangar
```

Supervisor 会将所有进程日志输出到 stdout。

## 二、线上部署（Nginx + Node.js）

线上环境**不部署原始源码**，只部署编译后的产物。前端为静态文件由 Nginx 托管，后端为编译后的 JS 由 Node 运行，systemd 负责进程管理。

### 部署流程

线上部署分为两个阶段：

| 阶段 | 操作位置 | 内容                      |
| -- | ---- | ----------------------- |
| 构建 | 开发机  | 编译数据、构建前端、编译后端          |
| 部署 | 服务器  | 上传产物、配置 Nginx、安装依赖、启动服务 |

### 1. 开发机：生成部署产物

在开发机上执行以下命令，生成可上传的部署文件。

```powershell
# 1. 编译站点数据（Markdown -> JSON）
python tools/builder/build_service.py --clean --data-root <数据目录> --output-dir <编译输出目录>

# 2. 构建前端静态文件，输出到 src/client/dist/
cd src/client
npm install
npm run build

# 3. 编译后端 TypeScript，输出到 src/server/dist/
cd ../server
npm install
npm run build
```

最终需要上传到服务器的产物：

| 产物     | 来源路径                                           | 服务器目标路径                       | 说明                                    |
| ------ | ---------------------------------------------- | ----------------------------- | ------------------------------------- |
| 前端静态文件 | `src/client/dist/`                             | `<应用目录>/dist/`                | Nginx 托管                              |
| 后端编译结果 | `src/server/dist/` + `src/server/package.json` | `<应用目录>/server/`              | Node 直接运行                             |
| 网站数据   | 编译输出目录                                         | `<应用目录>/my_sites_data/build/` | 由 `config.yaml` 的 `buildOutputDir` 指定 |

### 2. 服务器：上传产物

将上述产物上传到服务器后，目录结构如下（`<应用目录>` 为服务器上的部署根目录，如 `/opt/site-hangar`）：

```
<应用目录>/
├── server/
│   ├── dist/
│   ├── package.json
│   └── node_modules/      # 服务器上安装后生成
├── dist/                  # 前端静态文件
└── my_sites_data/
    ├── conf/
    │   └── config.yaml    # buildOutputDir、icp 等配置
    └── build/             # 编译后的 JSON 数据
```

### 3. 服务器：配置 Nginx

线上 Nginx 为每个站点添加一个 `server` 块，包含三部分：

| 配置块              | 作用                                      |
| ---------------- | --------------------------------------- |
| `root` + `index` | 托管前端 dist 静态文件                          |
| `location /api/` | 反向代理到 Node.js 后端（默认 3000 端口）            |
| `location /`     | SPA fallback，所有非 API 路径回退到 `index.html` |

在现有 Nginx 配置中新增：

```nginx
server {
    listen 80;
    server_name your-site.example.com;
    root <应用目录>/dist;
    index index.html;

    location /api/ {
        proxy_pass         http://localhost:3000;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }

    # SPA fallback：所有非 API 路径回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

多站点时，为每个域名添加独立 `server` 块，`server_name` 对应数据目录名，其余配置相同。修改后执行：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 4. 服务器：安装后端依赖

进入后端目录，安装生产环境依赖：

```bash
cd <应用目录>/server
npm install --omit=dev
```

### 5. 服务器：修改配置并启动

#### 5.1 修改 `config.yaml`

编辑 `<应用目录>/my_sites_data/conf/config.yaml`，确保 `buildOutputDir` 指向服务器上的数据目录：

```yaml
buildOutputDir: <应用目录>/my_sites_data/build
icp: ICP备20261111111号-1
```

#### 5.2 手动启动验证

```bash
cd <应用目录>/server
CONFIG_FILE=<应用目录>/my_sites_data/conf/config.yaml NODE_ENV=production PORT=3000 node dist/server.js
```

确认能正常访问后，改用 systemd 管理。

#### 5.3 systemd 服务配置

创建 `/etc/systemd/system/site-hangar.service`：

```ini
[Unit]
Description=SiteHangar Backend
After=network.target

[Service]
Type=simple
WorkingDirectory=<应用目录>/server
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=CONFIG_FILE=<应用目录>/my_sites_data/conf/config.yaml
ExecStart=/usr/bin/node dist/server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

常用命令：

```bash
sudo systemctl daemon-reload
sudo systemctl enable site-hangar    # 开机自启
sudo systemctl start site-hangar     # 启动
sudo systemctl restart site-hangar   # 重启（代码更新后）
sudo systemctl status site-hangar    # 查看状态
journalctl -u site-hangar -f         # 查看日志
```

### 6. 网站数据 build 结果的使用

网站数据由 `build_service.py` 编译生成 JSON，后端每次请求实时读取。

| 操作               | 是否需要重启后端 |
| ---------------- | -------- |
| 首次部署数据           | 否        |
| 更新数据内容           | 否        |
| 修改 `config.yaml` | 是        |
| 更新后端代码           | 是        |
| 更新前端代码           | 否        |
