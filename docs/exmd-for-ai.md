# EXMD 格式规范（AI 生成指南）

EXMD（Extended Markdown）是 SiteHangar 的文章源格式，完全兼容标准 Markdown，并扩展了可视化控件和布局能力。AI 生成内容时，请严格遵循以下规范。

## 文件组织规则

### 单文件模式

- 一个文章对应一个 `page.md` 文件
- 适用于简短笔记、备忘、单章节内容
- 文件内包含 frontmatter 和全部正文

### 多文件模式

- 一个文章对应一个文件夹
- 必须包含 `meta.md` 和至少一个章节文件
- 章节文件名格式：`01-章节名.md`、`02-章节名.md`，数字前缀控制顺序
- 适用于长文、多章节内容

**编译器检测顺序**：
1. 存在 `meta.md` + `01-xxx.md` → 多文件模式
2. 存在 `page.md` → 单文件模式
3. 无 Markdown 文件 → 不编译

## frontmatter 规范

所有 Markdown 文件必须包含 YAML frontmatter。

### 单文件模式 `page.md`

```yaml
---
title: 文章标题
subtitle: 文章副标题（可选）
introduction: 文章引言（可选）
tags:
  - 标签1
  - 标签2
---
```

### 多文件模式 `meta.md`

```yaml
---
title: 文章标题
subtitle: 文章副标题（可选）
introduction: 文章引言（可选）
tags:
  - 标签1
  - 标签2
---
```

### 多文件模式章节文件 `01-xxx.md`

```yaml
---
title: 章节标题
subtitle: 章节副标题（可选）
---
```

## 标题使用规则

| 标题级别 | 用途 | 规则 |
|---------|------|------|
| `#` H1 | 文章标题 | 正文中禁止使用，标题只来自 frontmatter |
| `##` H2 | 章节标题 | 单文件模式作为章节拆分标记；多文件模式禁止使用 |
| `###` H3 | 正文子标题 | 正常使用 |
| `####` H4 | 正文二级子标题 | 正常使用 |
| 五级以上 | 不支持 | 禁止使用 |

**核心规则**：
- 单文件模式：`##` 用于拆分章节，标题取自 `##` 文本
- 多文件模式：章节由文件拆分，`##` 被忽略，章节标题取自 frontmatter
- 正文中的 `###` 渲染为 `<h3>`，`####` 渲染为 `<h4>`

## 扩展控件语法

扩展控件有两种数据提供方式，根据数据量选择：

| 方式 | 语法 | 适用场景 |
|------|------|---------|
| 引用外部 JSON | `![type](data/xxx.json)` | 数据量较大、需要复用、AI 并行生成 |
| 内嵌数据 | code 块 `type` | 数据量较小、一次性使用 |

### 统计卡片

展示关键数值。

```markdown
![stats](data/stats.json)
```

```json
[
  { "label": "总文章数", "value": 128, "unit": "篇" },
  { "label": "总字数", "value": 256, "unit": "万字" }
]
```

### 卡片列表

多卡片并列展示。

```markdown
![cards](data/cards.json)
```

```json
[
  { "title": "卡片标题", "description": "描述文字", "image": "image/xxx.jpg", "tags": ["标签"] }
]
```

### 时间线

时间序列事件。

```markdown
![timeline](data/timeline.json)
```

```json
[
  { "date": "2024-01", "title": "事件标题", "description": "事件描述" }
]
```

### 分支图

多阶段分支对比。

```markdown
![branches](data/branches.json)
```

```json
[
  { "name": "分支A", "items": ["阶段1", "阶段2"] },
  { "name": "分支B", "items": ["阶段1", "阶段2"] }
]
```

### 标签芯片

标签云或关键词展示。

```markdown
![chips](data/chips.json)
```

```json
[
  { "label": "标签文字", "accent": true }
]
```

### 树状图

层级结构展示。

```markdown
![tree](data/tree.json)
```

```json
{
  "name": "根节点",
  "children": [
    { "name": "子节点1", "children": [] }
  ]

```

### 图表

支持柱状图、饼图、折线图。

```markdown
![bar](data/bar.json)
![pie](data/pie.json)
![line](data/line.json)
```

```json

  "xAxis": ["A", "B", "C"],
  "series": [{ "name": "系列1", "data": [10, 20, 30] }]

```

### 分栏

将内容分为多栏展示，最多 4 栏，不可嵌套。

```markdown
=====
左侧内容
-----
右侧内容
=====
```

## 图片引用

- 页面级图片放在文章目录的 `image/` 子目录下
- 引用语法：`![描述](image/xxx.jpg)`
- 图片路径相对于当前文章目录

## 内容层级

文章内容逻辑层级：文章 → 章节 → 段落 → 元素。

- 文章：由 frontmatter 定义标题、副标题、引言、标签
- 章节：由 `##` 或章节文件定义，包含标题、副标题
- 段落：章节下的内容单元
- 元素：文本、图片、图表、表格、列表、分栏等

## 数据文件引用

- 大数据量内容必须引用外部 JSON 文件，不要内嵌
- 引用路径：`data/xxx.json`，相对于当前文章目录
- JSON 文件必须有效，字段名与控件要求一致
- 生成数据文件时，确保数值类型正确（字符串加引号，数字不加）

## 生成规范

1. **先写 frontmatter**，再写正文
2. **章节拆分**：单文件模式用 `##` 拆分，多文件模式用多个文件
3. **控件选择**：数据量大用引用，数据量小用内嵌
4. **避免嵌套**：分栏不可嵌套，扩展控件内部不再使用扩展控件
5. **标题检查**：正文不用 `#` 和 `##`，只用 `###` 和 `####`
6. **文件命名**：章节文件使用 `01-`、`02-` 等数字前缀，确保顺序正确

## 错误示例

```markdown
# 错误：正文使用 H1
# 文章标题

## 错误：多文件模式正文使用 H2
## 第一章

##### 错误：使用五级标题
```

## 正确示例

```markdown
---
title: 人工智能发展史
subtitle: 从图灵测试到深度学习
tags:
  - AI
  - 历史
---

### 早期探索

人工智能的概念最早由图灵提出...

### 深度学习时代

随着计算能力提升...
```
